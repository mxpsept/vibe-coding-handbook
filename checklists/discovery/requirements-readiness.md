# Gate 1 — Requirements Readiness Checklist

> 判断 Discovery Evidence 是否足以进入 Requirements Engineering。不是判断系统是否已经可以开发。

## Problem Evidence

- [ ] 核心 Problem 已有 Evidence 支撑
- [ ] 不再仅依赖项目发起人的主观描述
- [ ] 关键 Pain 已识别 Who / When / Impact
- [ ] 主要 Job 已识别
- [ ] 至少部分高优先级问题拥有 E3 或更高 Evidence，或已明确记录证据缺口

## Stakeholders

- [ ] 主要 Stakeholder 已识别
- [ ] 高 Decision Power 角色已覆盖
- [ ] 高频 Operator / Executor 已覆盖
- [ ] 已识别主要 Business Rule Owner
- [ ] 没有只听管理者而忽略执行者

## Process

- [ ] 已形成可 Review 的 As-Is Process
- [ ] 关键流程步骤可以回溯 Source
- [ ] 已记录制度流程与实际操作的差异
- [ ] 已记录关键例外路径

## Evidence Quality

- [ ] Fact / Assumption / Unknown 分开
- [ ] Finding 可回溯到 Evidence
- [ ] Feature Request 与 Requirement 分开
- [ ] Business Rule Candidate 尚未被未经验证地冻结
- [ ] 冲突没有被 AI 擅自消除
- [ ] Synthetic Evidence 没有被伪装成真实研究

## Scope Readiness

- [ ] 能描述主要问题域
- [ ] 已识别高影响 / 高频 Pain
- [ ] 已识别明显 Out-of-Scope 候选
- [ ] 已知道 Requirements 阶段需要正式定义哪些规则
- [ ] 当前没有因为 UI 或技术方案提前锁死 Solution

## Decision

- [ ] PASS — Enter Requirements Engineering
- [ ] HOLD — Continue Discovery
- [ ] PIVOT — Reframe Problem
- [ ] STOP / PARK
