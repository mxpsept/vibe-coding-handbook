# INT-001 — 督办专员访谈

> **Synthetic Teaching Case**：以下内容完全虚构，仅用于演示 Discovery 方法，不代表真实用户研究。

## Metadata

- Source ID: INT-001
- Stakeholder: 督办专员
- Evidence base level: E2 — Stakeholder Statement
- Scenario: 周度经营会重点任务跟踪

## Interview Excerpt

**研究者：** 请回忆最近一次准备经营会督办材料的过程。

**督办专员：** 一般周五开会，我周四下午开始汇总。几个部门会把自己的 Excel 发过来，有的直接在群里说进展。我先看上周表格，再把这周的信息合进去。

**研究者：** 哪一步最花时间？

**督办专员：** 没更新的最麻烦。我得一个个在群里问，有时部门说负责人换了，我还得重新找人。正常大概两个小时，事情多的时候半天都有可能。

**研究者：** 最近一次出现信息不一致是什么情况？

**督办专员：** 有一项部门负责人在群里说已经完成了，但发来的 Excel 还是 80%。我最后又确认了一次才改。

**研究者：** 你怎么判断哪些事情需要重点关注？

**督办专员：** 主要看时间快到了还没完成的，还有很久没更新的。但具体提前几天算临期，现在没有特别统一，有些重点任务领导会单独问。

**研究者：** 如果有一个新系统，你最希望它做什么？

**督办专员：** 最好自动告诉我哪些没更新、哪些快超期，我不用每周重新筛。

**研究者：** 如果先不讨论系统，你真正想完成的事情是什么？

**督办专员：** 周会前能很快知道哪些任务有风险、现在卡在哪里，别到会上才发现信息不对。

## Initial Analysis

### Statements

- 周四通常需要准备周五经营会材料；
- 部门通过 Excel 和群消息反馈进展；
- 未更新事项需要人工询问；
- 负责人可能发生变化；
- Excel 与即时通讯中的状态可能不一致；
- 当前“临期”定义可能不统一。

### Pain Candidate P-001

```text
Who: 督办专员
When: 周会前汇总
Behavior: 收集多个来源并人工确认未更新事项
Pain: 信息分散且状态可能不一致
Impact: 自述通常约 2 小时，繁忙时可能半天
Evidence: INT-001 / E2
Validation needed: Observation + historical artifacts
```

### Job Candidate J-001

```text
在经营会前快速获得可信的风险事项清单，
知道哪些任务需要关注以及当前阻塞原因。
```

### Feature Request FR-001

```text
“自动告诉我哪些没更新、哪些快超期。”
```

Status: Feature Request only — NOT Requirement.
