# vibe-workspace-kit v0.2 Delivery Roadmap

v0.2 应以小步兼容方式实现，避免一次加入 workflow engine、LLM、Issue Tracker 等过多能力。

## Phase 0 — Contract Spike

目标：证明 Artifact Contract 可以被人、Agent、CLI 同时使用。

产出：
- schema/type draft；
- sample project artifacts；
- parser/validator spike；
- FlowOps sample feature。

Exit：CLI 能 deterministic 读取 Feature ID、status、repos、AC 和 verification references。

## Phase 1 — Bootstrap

实现：
- optional `artifacts` config；
- `vibe bootstrap`；
- minimal templates；
- idempotent generation；
- existing-file safety。

测试重点：重复执行、已有 docs、Windows path、partial workspace。

## Phase 2 — Feature Workspace

实现：
- `feature create`；
- feature metadata parser；
- `feature status`；
- local active-feature state。

此阶段不自动 branch/snapshot，先稳定 Artifact lifecycle。

## Phase 3 — Feature Start

将已有能力组合起来：

```text
validate
→ branch selected repos
→ snapshot selected repos
→ active feature
→ context bundle
```

任何一步失败必须给出恢复状态，避免多个 repo 一半切分支、一半未切换却显示成功。

## Phase 4 — Context & Adapters

实现 canonical context builder，再适配：
1. Codex/AGENTS；
2. Claude；
3. Cursor/Copilot。

不要反过来从现有模板复制四套逻辑。

## Phase 5 — Engineering Check

实现 deterministic checks：
- artifacts/schema；
- SPEC_GAP；
- AC/verification coverage；
- repo references；
- snapshot/test freshness；
- generated context drift。

支持 machine-readable output：

```bash
vibe check TASK-102 --json
```

为 CI 集成做准备。

## Phase 6 — Feature Close

只有当 `check` 稳定后再实现 close gate。

```text
close != merge
close != push
```

它只表示本地 Engineering Contract 达到团队定义的完成条件。

## Phase 7 — CI / Ecosystem

v0.2 核心稳定后再考虑：
- GitHub Action；
- PR summary；
- Jira/GitHub Issue adapters；
- template registry；
- organization policy packs；
- optional AI-assisted semantic review。

这些不应阻塞 v0.2。

## Recommended First Implementation PRs

```text
PR1 types + artifact config + fixtures
PR2 bootstrap templates/generator
PR3 feature create/status
PR4 feature start orchestration
PR5 canonical context builder
PR6 Codex adapter + migration compatibility
PR7 check engine + JSON result
PR8 docs + end-to-end FlowOps test
```

每个 PR 都应保持 0.1.x tests green。

## Release Strategy

建议先发布：

```text
0.2.0-beta.1
```

用至少两个不同形态项目验证：
- frontend + backend polyrepo；
- 单仓或 backend + contracts 等非典型组合。

稳定后发布 `0.2.0`，并明确 0.1.x workspace 用户无需采用 Artifact System 即可升级。
